## Section A: Step 5 — Database N+1 Query Optimization

### 1. Root Cause Identification
- **`GET /api/v1/orders/` & `GET /api/v1/staff/orders/`**:
  - Serializer called `obj.payments.order_by("-created_at").first()` across 3 separate serializer methods (`payment_method`, `payment_status`, `payment_gateway`), triggering **3 SQL queries per order row** because `.order_by()` bypasses Django prefetch cache.
  - Line items triggered separate queries for `variant`, `product`, and reverse relation `product.images`.
  - `status_history` and `user.email` were queried per order.
- **`GET /api/v1/staff/dashboard/`**:
  - Fired separate unaggregated queries for total orders, orders today, pending orders, captured revenue, order revenue, pending COD payments, pending UPI payments, product counts, stock alerts, user counts, plus un-prefetched recent orders and payments.

### 2. Implementation
- In `apps/orders/models.py`, implemented custom `OrderQuerySet.with_details()` that eager-loads `user`, `payments` (ordered), `status_history` (with actor), `lines` (with variant, product, and active images) in a single batch.
- In `apps/orders/serializers.py`, implemented `_get_latest_payment()` with local instance caching and prefetch cache inspection (`obj._prefetched_objects_cache['payments']`).
- In `apps/accounts/staff_dashboard_view.py`, collapsed multiple metrics into single conditional aggregation queries (`Count(Case(When(...)))`, `Sum(Case(When(...)))`) and prefetched `attempts` on recent payments.

### 3. Measured Results (Before vs. After)

| Target Endpoint | Metric | BEFORE Optimization | AFTER Optimization | Delta / Improvement |
|---|---|---|---|---|
| **`GET /api/v1/orders/`** (Customer) | **SQL Queries** | **48 queries** | **6 queries** | **-87.5% queries** |
| | Response Time | 14.34 ms | 6.70 ms | **53.3% faster** |

## Section B: Step 6 — Staff Inventory Endpoint Mapping Fix

### 1. Root Cause Identification
- Backend endpoint at `/api/v1/staff/inventory/<uuid:pk>/` implemented `PATCH` only for updating stock on `StockItem`.
- Frontend `adminService.updateStock` sent `POST` and passed `selectedItem.variant_id` (which was undefined because `StockItemSerializer` omitted `variant_id`).
- Backend lacked `GET` endpoint for retrieving individual inventory item details.

### 2. Implementation
- In `apps/inventory/serializers.py`: Added `variant_id = serializers.UUIDField(source="variant.id", read_only=True)` to `StockItemSerializer`.
- In `apps/inventory/staff_views.py` (`StaffInventoryUpdateView`):
  - Added `get_stock_item()` helper resolving `pk` as either `StockItem.id` OR `variant.id`.
  - Implemented `GET` method to return inventory details.
  - Supported both `PATCH` and `POST` methods for seamless backward compatibility.
- In `frontend/services/adminService.js`:
  - Updated `updateStock` to use `api.patch('/staff/inventory/${stockItemId}/')`.
  - Added `getInventoryItem(stockItemId)`.
- In `frontend/app/admin/inventory/page.js`:
  - Passed `selectedItem.id || selectedItem.variant_id`.

### 3. Verification
- Unauthenticated access: **401 Unauthorized**
- Customer access: **403 Forbidden**
- Staff GET list: **200 OK** (retrieved 20 items)
- Staff GET item details by StockItem UUID: **200 OK**
- Staff GET item details by Variant UUID: **200 OK**
- Staff PATCH stock update: **200 OK** (quantity adjusted and verified)

## Section E: Step 9 — Frontend Performance & Bottlenecks

### 1. Eliminated Bottlenecks
- **Trailing Slash 308/301 Redirect Loop**: Next.js `skipTrailingSlashRedirect: true` and `/api/v1/:path*/` canonical rewrite completely eliminated browser redirect freezes.
- **Guest Auth 401 Cascade**: `AuthContext.jsx` short-circuits `initAuth` when no token exists, and `apiClient.js` exempts `/auth/me` from triggering silent token refresh loops.
- **In-Flight Request Deduplication**: Added concurrent request caching in `ApiClient.request` for in-flight GET requests, preventing duplicate simultaneous calls to categories and featured products.
